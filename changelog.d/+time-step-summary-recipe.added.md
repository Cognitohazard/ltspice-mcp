`analyze_results` has a `time_steps` recipe that reads a transient run's time axis and reports, per run and per step of a stepped run, the stored points, the smallest step and where it starts, the largest and the median step, and with `threshold_s` how many steps were shorter and where the first and last start. Over a job it gives one row per run, so the run whose time step collapsed stands out. Its `stored` field says whether the file holds every point the solver accepted, and when it does not, or when that was not checked (LTspice XVII's default waveform compression, ngspice under `.options interp`, LTspice 26, a run saved from a `.tran` start time), the reply says what that leaves out.
