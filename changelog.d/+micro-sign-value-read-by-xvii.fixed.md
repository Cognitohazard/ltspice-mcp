A value written with a micro sign or a Greek mu (`1µ`, `1μ`) in a deck stored as UTF-8 is micro to the server and to LTspice 26, but LTspice XVII reads the same bytes as the bare number (1 farad for `C1 out 0 1µ`), and nothing said so. When a session runs LTspice XVII, every reply that gives a value, or a comparison of values, read from a stored deck now says so: `inspect(kind="hierarchy")`, the `comparison` of `verify_circuit` and `edit_schematic`, and a run's receipt (a `value_read_otherwise` observation, which covers a Monte Carlo nominal drawn from the deck). Each file gets one summary per build: how many values, a few examples with the text that build reads and the number it takes, and the call that lists them all. Where no recording shows the number a build takes, the summary says so. A sheet is judged by its own bytes, so a sheet that writes `u` is never reported. `verify_circuit` no longer warns that LTspice XVII misreads a micro sign in a UTF-16 deck: the recordings show it reads it as micro.
