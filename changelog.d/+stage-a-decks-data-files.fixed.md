A run now stages the data files a deck reads, with the deck: on LTspice a source's `wavefile=` (also written `wavefile level.wav`, with no `=`) and a PWL source's `file=`, on ngspice a `filesource` model's `file=`. Before, the run started from a copy of the deck in another folder, where a relative data path named no file, so a deck that ran when the simulator was started on it directly failed, or read another file, through the server, in a plain run, in each case of a variation or Monte Carlo set and in a detached job. A relative path is read from the deck's folder, as both simulators read it, the file is copied byte for byte, and the staged card names the copy. A data file that does not exist (`data_file_missing`) or lies outside `[security] allowed_paths` (`data_file_outside_allowed_paths`) is refused before the run, naming the card and where the file was looked for. A data file named by an absolute path is read where it is and reported (`live_data_file`). On LTspice a relative data path in an included file is refused (`data_file_unestablished`), because which folder LTspice reads it from is not recorded, and a run reports that LTspice reading the staged copy by its absolute path is not recorded either (`data_path_unrecorded`). A recoverable run now admits the data cards it stages, since it saves the copy with the deck.

A deck with a data file named by an absolute path is read in place, so like a live include it is now refused for a replay of its `request_id`, for native statistics and for a recoverable run, all of which need every input digested.
