A value that is missing or ambiguous now says why on every route that returns it, through the tools and the Python API. An empty device operating-point table read by job carries `logopinfo_withheld` when the run was made without `.options logopinfo`, and one read by path carries `device_table_request_unknown`, since no job record says whether the table was asked for. A measurement LTspice printed as a number that is not finite (a stepped `.fra` gain margin of `infdB`) is null with `unreadable` quoting what the log printed, on the measurements and summary recipes, `inspect` and `api.measurements`; the measurements recipe's `not_finite` list is gone. A measurement LTspice 26 prints once for a stepped `.op` carries `printed_once`: the run's step count, the step whose value it is (the first, established by comparison with a recorded results file of the same circuit), and the recipe that reads the other steps.
