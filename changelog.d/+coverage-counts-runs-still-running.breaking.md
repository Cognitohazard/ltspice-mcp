`analyze_results` lists in `coverage.missing_cases` only the cases that cannot be read, each with its own code (`run_not_finished` for a case still queued or running, `raw_not_produced` for one that ended without results), in place of one `job_not_terminal` row for a whole job that had not ended, and `coverage.runs_requested` now counts each requested case of such a job. The new `coverage.runs_running` counts the runs asked for that have not finished, so a value over the runs read is not taken for the result of a job that has not ended.
