`execution.results_beside_sheet` and `jobs(action="place_beside_sheet")` now take a netlist as they take a sheet: the run's results and log are copied beside the netlist under its name, where LTspice's own batch run writes them, and the reply says that what LTspice's window does with results beside a netlist has not been checked. The refusal `not_a_sheet` is gone. A job whose circuits would put more than one case into one results file is refused with `several_cases_per_sheet`, which now names the circuits and the file: `foo.asc` and `foo.net` both go to `foo.raw`, and one circuit named twice by two spellings is caught too. A netlist with a sheet of its name beside it is refused with the new code `results_belong_to_sheet`, because that results file is what LTspice's window shows as the sheet's run. Whether a job's simulator has its results put beside a circuit is now read from the capability table, so a job record naming a simulator the server does not know is refused with `not_ltspice` where it was let through. A placement whose job holds no digest for the circuit now says it was not compared with the file that ran, for a sheet as for a netlist, where it said nothing before.
