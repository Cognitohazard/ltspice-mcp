The `.save` and `.meas` coverage check reads each name as the simulator that runs the deck stores it. On ngspice it no longer refuses a `.meas` of `v(x1:mid)` when `.save v(x1.mid)` stores the node, and it reports a `.save` of `v(x1:mid)`, which ngspice drops without a word (`save-name-not-stored`). On LTspice a `.meas` of a node inside a subcircuit spelled as the other build spells it (`xa:xin:mid` on XVII, `a:in:mid` on LTspice 26) is refused, as it reads nothing on either setting; spelled as the build spells it in a deck with no `.save` list, it is a warning (`meas-subckt-node-unsaved-ltspice`), since LTspice keeps the node only with its "Save subcircuit node voltages" setting on. Where the build's spelling is not established (a dotted path in an LTspice deck, a build not yet known), the check says so (`save-meas-spelling-unestablished`) and does not refuse.

A device inside a block placed as U1 is `xu1.d1` to `api.device_op_points` and the `operating_point` recipe on LTspice 26 as on XVII (it was `u1d1` on LTspice 26); `api.device_op_points(...).table_names` gives the name the log's table used.

Node, net and trace names are compared in ASCII case only, the same way everywhere: `maß` and `mass` are no longer one name to some checks and two to others. A deck for ngspice with a node name beyond ASCII gets a warning (`node-non-ascii-ngspice`): ngspice replaces each such byte with `_`, so `aé` and `aè` become one node.

A noise contribution of a device whose name holds `inoise` (`V(Rinoise)`) is no longer taken for the input-referred noise and given the input source's unit.
