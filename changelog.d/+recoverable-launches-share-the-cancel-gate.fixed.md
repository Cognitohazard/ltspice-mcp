The launches of one job run with `execution.recoverable` no longer take turns, and a slow write no longer fails a healthy case. Each launch held the job's cancellation lock while it waited for its launch record to be written, so the job's other launches waited for that write, and any that waited longer than the lock's ten-second timeout failed with `submission_failed`. A cancel from another server process waited behind the same write and could time out. Each write of a job's record also waited for the one before it. Now a launch holds the lock only to decide whether it may start, and the writes of a job run side by side with only the newest reaching disk, so a held write no longer holds back another case's launch record or a cancel.
