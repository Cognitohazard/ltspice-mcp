A job run with `execution.recoverable` no longer hangs the server when its parallel launches, or the launches of recoverable jobs on two simulators at once, outnumber the threads the server offloads file work to. Each launch waited for its launch record to be written while holding one of those threads, so with all of them waiting no record could be written, the job never finished, `jobs(action="cancel")` could not end it, and every other read the server offloads stalled with it. Launches now run on threads of their own, and a cancel, deadline or shutdown of the job ends a launch that is still waiting for its record: the simulator is not started and the case reports that it was cancelled.
