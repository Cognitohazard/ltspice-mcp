The `summary` recipe's `errors`, `warnings` and `meas_errors`, and the `severity` of each line it relays, now come from the run's classified diagnostics, the source of the run row's `diagnostics`, so the two no longer disagree about what the simulator said or how severe it called it. Each distinct line on which the simulator wrote an error or a warning word is listed, by that word; a repeated identical line is one entry, and past 50 distinct lines of one condition a new `lines_left_out` says how many more there were. A line with no such word is in neither list and stays in `diagnostics`: LTspice's bias-point stepping rungs and its iteration limit, LTspice 26's failed operating point and its `file(N): …` deck messages (including one for a `.meas` it cannot read, which no longer gives a `meas_errors` entry), and ngspice's `Note:` lines. LTspice XVII's failed operating point is listed as its `Fatal Error: … trouble with node "…"` line. A relayed line with no word of the simulator's own carries no `severity`, where it used to say `error`, and an error that names a `.meas` is relayed once, as that measurement. A diagnostic's `severity` on the run row is the strongest word over its occurrences. For QSPICE and Xyce, whose log wording the server has no recordings of, lines are read with the patterns the server used before it had recordings, now counted as the `simulator_error` and `simulator_warning` diagnostics, so their summary lists the same lines as before; such a line carries a `severity` only where the simulator wrote a word on it. `meas_batch_abort` no longer claims that LTspice abandons the other `.meas` after one fails, which no recording shows: it fires only when the log holds no measurement, says on LTspice 26 that the deck was refused, and elsewhere that the cause is not established and which recording would settle it. A `.meas` or `.four` ngspice skips in batch mode is still reported as skipped, read from the new `measurement_skipped_batch` and `fourier_skipped_batch` diagnostics; ngspice's notices are no longer in `warnings`.
