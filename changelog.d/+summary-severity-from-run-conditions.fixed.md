The `summary` recipe's `errors`, `warnings` and `meas_errors`, and the `severity` of each line it relays, now come from the run's classified diagnostics, the source of the run row's `diagnostics`, so the two no longer disagree about what the simulator said or how severe it called it. A condition is an error or a warning only where the simulator wrote that word on it, and its severity is the strongest word it wrote on any of its lines (LTspice XVII's failed operating point, whose `Fatal Error` comes on a later line, is an error). Each list holds one entry per condition, as `diagnostics` counts it. A line with no such word is in neither list and stays in `diagnostics`: LTspice's bias-point stepping rungs and its iteration limit, LTspice 26's `file(N): …` deck messages (including one for a `.meas` it cannot read, which no longer gives a `meas_errors` entry), and ngspice's stepping notes. A relayed line with no word of the simulator's own carries no `severity`, where it used to say `error`. An error that names a `.meas` is relayed once, as that measurement, and its own miss no longer claims that LTspice abandoned the other measurements. For QSPICE and Xyce, whose log wording the server has no recordings of, the run row's `diagnostics` now tell apart the lines the simulator starts with `Error:` or `Warning:`, and the summary lists those. A `.meas` ngspice skips in batch mode is still reported as skipped, read from a new `measurement_skipped_batch` condition; its advice line is no longer in `warnings`.
