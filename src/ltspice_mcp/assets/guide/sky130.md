# Native Sky130 statistical samples

The `pdk_native` variation runs the statistical models of a specific PDK
installation. The one supported profile is the generated Sky130A model set at
open_pdks revision `e6f9c8876da77220403014b116761b0b2d79aab4` and its
`sky130_fd_pr__nfet_01v8` devices. The PDK is installed separately, and when a
sandbox is set (`[security] allowed_paths`), the PDK must be inside it. Every
PDK file that the deck loads is checked against the SHA-256 hashes recorded in
the profile, so a similarly named or edited installation is refused.

Author the bench with the PDK's ngspice library and the section that matches
the variation's `mode`: `tt` for `"nominal"`, `tt_mm` for `"mismatch"`, or `mc`
for `"process"` samples.

```spice
.lib "path/to/sky130A/libs.tech/ngspice/sky130.lib.spice" tt
```

For `mode: "combined"`, use section `mc` and put `.param mc_mm_switch=1` in
your own deck, at the top level, after the `.lib` line. Use exactly one `.op`,
`.tran` or `.ac`. Give each device `m`, `mult` and `nf` of 1 and a W and L that
evaluate to positive numbers. Omit `.control` blocks, `.step`, `.setseed`, and
any setting of `seed`, `randomseed`, `mc_pr_switch`, `ngbehavior`,
`ng_nomodcheck`, `scale` or a top-level parameter that the PDK defines (apart
from that one `mc_mm_switch=1`), because the server starts ngspice on its own
control script that sets the mode and seed before loading the deck. A MOS
device other than `sky130_fd_pr__nfet_01v8`, or any other analysis, fails with
a reason.

```json
{"kind": "pdk_native", "id": "samples", "profile": "sky130-e6f9c887-ngspice-v1",
 "mode": "combined", "runs": 20, "seed": 1947}
```

Add that entry to `run_experiments.variations` with `execution.simulator` set to
`ngspice`. `assign` variations can be added to the same call. Each sample runs
in a new ngspice process, which sets the sample's seed before the PDK models
load. That seed is computed from the variation's `seed`, `id`, `mode` and
sample index, the circuit id, the contents of the input files and the `assign`
values. For sample 7 alone, keep the inputs, ids, assignments and seed, then
set `runs: 1, sample_start: 7`. Parallel limits and job ids do not change the
seed, so they do not change a sample's values. Exact reproduction also needs
the simulator build and platform that the run records.

Inspect `native_statistics` in run receipts, or request full details with
`jobs(action="runs", job_id=..., run_fields=["native_statistics"])`. Each fact
that is not available is listed under `unavailable` with a reason, including on
failed or skipped cases. The full record lists each
`sky130_fd_pr__nfet_01v8` device the samples apply to (`validated.coverage`),
a hash of the original PDK model files (`validated.model_digest`), the seed
the sample used (`validated.effective_seed`), the simulator that ran it
(`simulator`), and each prepared file with its hash (`prepared.dependencies`).
The PDK's internal random draws are not reported; compute the statistics of
your measurements from the runs.
